# apps/web

The public site (landing, docs, pricing, self-host, legal) and the dashboard. Commit only when the user tells you to.

## Look and feel

- The landing page is the reference design. Public pages render inside `SiteShell` and are built from `src/components/site/*`. Extend a shared component with a new optional prop; keep its existing look.
- Write every colour as a token from `src/index.css`: `bg-background`, `bg-card`, `text-fg` to `text-fg-4` (fg-4 is the dimmest readable text), `border-line` / `border-line-2`, `bg-fill` / `bg-fill-2`, and gold `bg-primary` / `text-primary`.
- Type: Martian Grotesk for text (`font-sans`), Martian Mono for code (`font-mono`), Hubot Sans for headings (`font-display`). `src/app/layout.tsx` loads them with width and size adjustments that keep line lengths stable; keep those when you touch the fonts.
- The landing demos are imperative: the markup renders once on the server and `src/components/landing/engine.ts` mutates it, with styles in `landing.css`. Change a demo's script in the engine. Hot reload does not rerun the engine, so reload the page to see an edit.
- Check every UI change in the browser at 1440px and 390px wide.
- The Notch mark's shape lives in `src/components/site/mark.tsx`. The images in `public/brand` and `public/favicon_io`, and the OG image rendered from `public/og-card.html`, are generated by the scripts in `marketing/brand/` (gitignored, on the owner's machine), so a change to the mark or the OG card means rerunning them.

## Docs

- A page is `content/docs/<slug>.md` with `title`, `description` and an optional `nav` (the sidebar label) in its frontmatter. `content/docs/nav.json` sets the order.
- Every page is also served as markdown (`/docs/<slug>.md`, or `Accept: text/markdown`) and collected in `/llms.txt` and `/llms-full.txt`, so agents read these docs as much as people do. Write for both: plain words, sentence case, short sentences, the exact commands and config to copy, and for each setting whether it is required, optional or not needed.
- Document shipped behaviour. Something planned gets a short "Coming soon" note.
- Show what users type and see; tool-call JSON stays in the plugin code.
- Link other pages as `/docs/<slug>`. The markdown output turns those into absolute `.md` links.
- The plugins are `@gitterm/opencode-sandbox` (the `sandbox_*` tools) and `@gitterm/opencode-cloud` (the `/cloud` command). Site copy takes install commands and provider facts from `src/lib/site/providers.ts`.

## Deployment modes

`NEXT_PUBLIC_DEPLOYMENT_MODE` is `managed` (gitterm.dev) or `self-hosted`, the default. The Docker image is built once and `docker-entrypoint.sh` fills the mode in when the container starts, so read it per request or in client code, never in anything decided at build time. A self-hosted deployment serves only the app; `src/proxy.ts` redirects or hides everything else.

## Checks

From the repo root: `bun run check-types`, then `bunx oxfmt <files>` and `bunx oxlint <files>` on what you changed.
